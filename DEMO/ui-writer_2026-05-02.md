## Source Material

Project name: UI-writer

GitHub link: https://github.com/jacky105402002/UI-writer

Project positioning:

- AI-assisted workflow for turning PM / MPL requirement documents into reviewable HTML wireframes and Figma-ready design material.
- Designed as a research workflow for early product discovery, MVP, POC, requirement interviews, client review, and AI agent collaboration.
- Focuses on structured requirements before UI generation, instead of asking AI to directly create polished UI screens.

Problem solved:

- Early requirements are often scattered across meeting notes, verbal descriptions, screenshots, tables, and personal notes.
- PMs, engineers, and designers can struggle to form the same understanding quickly.
- UI-writer makes the handoff more disciplined by separating requirement structuring, wireframe generation, and design continuation.

Core workflow:

- PM uses prompt files in `prompts/` to produce `SDD.md`, `UserFlow.md`, and `UI.md`.
- Codex / Claude Code reads those documents and uses the `requirements-to-wireframe` skill.
- The workflow produces `wiremd` source files, HTML wireframes, Figma import guidance, and a static prototype for PM / client review.
- Designers can import or reference the HTML output in Figma and continue toward a formal design.

Research value:

- The project intentionally produces grayscale, rough wireframes so the discussion stays focused on information architecture, flows, components, states, permissions, and business logic.
- It helps teams check missing pages, user flows, data fields, roles, client understanding, and designer handoff readiness earlier.

Demo case mentioned in the source:

- Resilience Hub OS, a public-site / school / community-center operations system for disaster-preparedness equipment, inventory, inspections, drills, contacts, alerts, and report export.

Suggested one-line summary:

`UI-writer` is an AI collaboration workflow that turns PM requirement documents into HTML wireframes and Figma-ready material, helping vague requirements become discussable, checkable, and designable interface prototypes.

我最近整理了一個小型研究專案：`UI-writer`。

它是一套把 PM / MPL 需求文件轉成 HTML 線稿與 Figma 可接續素材的 AI 協作工作流。重點不是直接叫 AI「幫我做漂亮 UI」，而是先把模糊需求整理成標準化文件，再讓 AI 根據文件產出可討論、可檢查、可交接的介面原型。

這個專案想解決的是產品早期很常見的問題：需求散落在會議紀錄、口頭描述、截圖、表格和筆記裡，PM、工程師、設計師很難快速形成同一個理解。

`UI-writer` 把流程拆成三段：

- PM 先用 `prompts/` 裡的提示詞整理出 `SDD.md`、`UserFlow.md`、`UI.md`
- Codex / Claude Code 讀取文件，透過 `requirements-to-wireframe` skill 產出 wireframe 與 HTML prototype
- 設計師再把 HTML 匯入或參考到 Figma，接續深化成正式設計稿

目前產出的內容包含：

- `wiremd` 線稿原始檔
- 可瀏覽的 HTML wireframe
- Figma 匯入指南
- PM / 客戶可以一起審閱的靜態 prototype

我覺得這個工作流有趣的地方在於，它刻意先產出灰階、粗糙、偏線稿的畫面，讓討論焦點停留在資訊架構、頁面流程、元件狀態、資料欄位、權限角色與業務邏輯，而不是太早陷入視覺細節。

這對 MVP / POC 很實用，因為團隊可以更早檢查：

- 頁面是否漏掉
- 使用者流程是否合理
- 資料欄位是否足夠
- 權限與角色是否清楚
- 客戶是否理解產品操作方式
- 設計師是否有足夠資訊接續深化

目前 DEMO 使用的是「韌性場域作業系統 Resilience Hub OS」案例，模擬公有場域、學校、社區中心在防災設備、物資、巡檢、演練、聯絡人、警示事件與成果報告上的管理需求。

我把 `UI-writer` 視為一個「AI 輔助產品規格到介面原型」的工作流實驗。它適合用在需求訪談後整理、MVP / POC 早期確認、客戶溝通，以及 AI agent 如何穩定協作產品開發流程的研究。
