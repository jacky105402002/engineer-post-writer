Date: 2026-05-02

## Source Material

Project name: MVP/POC Spec Builder

Project link:

- https://github.com/jacky105402002/mvp-poc-spec-builder

Project positioning:

- AI-assisted product specification workflow.
- Helps turn early product needs, user scenarios, goals, and constraints into an MVP/POC specification.
- Designed for AI agents and engineers to understand before moving into SDD, wireframe, static MVP, data modeling, API assumptions, or implementation.

Core outputs:

- MVP validation goals
- POC feasibility validation goals
- Core user flows
- Feature scope breakdown
- Screen list
- UI wireframe intent
- Static MVP generation brief
- Data model candidates
- API / backend assumptions
- Productization risks and follow-up questions

Key idea:

The project does not treat AI only as an automatic coding tool. Instead, it places AI earlier in the product discovery workflow, helping clarify requirements, split scope, mark assumptions, and identify unknowns before building.

Example demo case mentioned in the source:

- An internal booking and scheduling tool for a home cleaning company.

Research topics:

- AI agents in requirements engineering
- From unstructured needs to structured specifications
- MVP / POC / productization scope separation
- AI-ready specification document design
- Using specifications to constrain AI-generated UI and code
- Static MVP as low-cost product validation
- Human-AI collaboration in product discovery

我最近整理了一個研究型 Codex Skill 專案：MVP/POC Spec Builder。

這個專案想處理的不是「直接讓 AI 產 UI」或「直接叫 AI 寫 code」，而是產品開發更前面的問題：

當我們手上只有零散需求、使用者情境、產品目標和限制條件時，怎麼把這些資訊整理成一份 AI agent 和工程師都能理解的 MVP/POC 規格書。

它的目標是把早期產品探索轉換成更可執行的規格，例如：

- MVP 驗證目標
- POC 可行性驗證目標
- 核心使用者流程
- 功能範圍切分
- 畫面清單
- UI wireframe 意圖
- 靜態 MVP 生成 brief
- 資料模型候選
- API / backend 假設
- 產品化風險與後續問題

我覺得這個專案比較有研究價值的地方，是它把 AI 放在「產品規格形成」的流程裡，而不是只把 AI 當成自動寫程式的工具。

也就是說，先讓 AI 協助釐清需求、拆解範圍、標記假設與未知，再把結果交給後續的 SDD、wireframe、static MVP 或工程實作流程。

這比較接近一種 AI-assisted product discovery workflow：

從模糊需求到可執行規格，而不是從 prompt 直接跳到成品。

目前 repo 裡也有 demo，用「居家清潔公司內部預約排程工具」作為案例，展示如何把原始需求整理成完整的 MVP/POC 規格。

如果你也在研究 AI agent 如何參與產品設計、需求工程、規格文件生成或低成本原型驗證，這個方向應該會蠻有參考價值。
